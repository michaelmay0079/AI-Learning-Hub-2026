# 译校 · Karpathy《大型语言模型导论》（改编）

> **原文**：Andrej Karpathy《Intro to Large Language Models》（YouTube 演讲，2023–2024）。
> **说明**：本篇为其中文**译校/改编**，提炼核心概念与边界；版权归 Andrej Karpathy。核验日期：2026-11-09。

## 一句话定义

LLM 是在海量互联网文本上训练出的模型，核心能力是**预测下一个 token**。它的"智能"来自规模与数据，而非内置知识库。

## 关键概念

- **Token 与分词器（Tokenizer）**：文本先切成 token（子词/词片段），模型在 token 层面运算。
- **训练的三阶段**：
  1. **预训练**：在超大语料上做"下一个 token 预测"，此阶段形成通用语言能力（算力与数据消耗最大）。
  2. **监督微调 / 指令微调**：用精选的"指令—回答"数据，让模型学会按人类意图回应。
  3. **对齐（RLHF 等）**：用人类反馈让回答"有用、真实、无害"。
- **规模与涌现**：模型越大、数据越多、算力越足，能力可预测地增强；某些能力在规模阈值后"突然"出现。

## 真实边界（务必记住）

- **幻觉**：会自信地编造；输出不能当权威。
- **知识过时**：训练数据有截止日期，不实时。
- **不联网、不可靠计算**：不会真做精确算术或查实时事实，除非接工具。
- **上下文有限**：能"记住"的对话长度有限。

## 工具与智能体（Agent）

模型可外挂工具（搜索、代码执行、数据库），把"预测下一个词"升级为"完成一件事"。这正是 RAG 与 Agent 的由来。

## 开源 vs 闭源

开源权重可本地部署、修改、复现；闭源以 API 提供、能力常更强但不可控。选哪个取决于你的需求与约束。

## 给非从业者的结论

Karpathy 的提醒最中肯：**理解它能做什么、不能做什么，比追逐参数规模重要**。本仓库四层结构正是据此展开。
